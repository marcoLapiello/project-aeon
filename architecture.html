Production system overview

Aeon inference engine

A streaming Mixture-of-Experts runtime that keeps the active computation on AMD GPUs while moving only the expert weights that are likely to be needed.

1. Inference flow

Prompt or next token

The engine receives a prompt, or the next token request during generation.

→

GPU execution pipeline

Wave32 + WMMA
Shared computationAttention, normalization, and shared model structures stay resident.
Route tokensThe router selects the small set of experts needed by each token.
Run expertsResident experts execute immediately; results are merged into the layer output.
→

Generated output

The next token is returned, or the completed response is emitted to the user.

2. Expert memory hierarchy

Hot: GPU VRAM

The execution surface. It contains the structures that must always be fast.

  • Attention and router networks
  • Shared experts and active KV cache
  • LRU cache of routed experts

Warm: host RAM

A pinned staging area that keeps likely expert candidates close to the GPU.

  • Prefetch queues
  • Secondary expert candidates
  • Fast DMA path to VRAM

Cold: NVMe storage

The long-tail repository for experts that are not currently active.

  • Asynchronous direct reads
  • 4 KB-aligned expert blocks
  • Optional parallel drive channels

Prediction and movement happen ahead of execution

Expert history and co-activation patterns guide speculative prefetching several layers ahead. NVMe to RAM to VRAM transfers use double-buffered asynchronous queues, so compute and movement overlap.

Cold misses do not stop the GPU

If an expert is absent from both fast tiers, the host CPU can compute that expert from RAM. Only its small activation result crosses PCIe and rejoins the GPU result.

3. Scaling across GPUs

Pipeline parallelism

Each GPU owns a consecutive group of model layers. During execution, only compact intermediate activations cross the PCIe boundary.

GPU stage 1Early layers
GPU stage 2Middle layers
GPU stage 3Later layers

Why this topology

Expert weights stay local to the layers that use them. While one stage computes, downstream stages have time to prefetch their next experts. With concurrent micro-batches, the pipeline stages work at the same time.

4. Operating principles

Keep the GPU busy

Storage is a background source, never a synchronous dependency for the active compute step.

Exploit locality

Frequent experts remain in fast memory; sparse routing makes the model practical on consumer hardware.

Use every tier

VRAM, host RAM, NVMe, and CPU cores cooperate as one bandwidth-adaptive system.

Stay hardware-native

Execution is tuned for AMD RDNA hardware, Wave32 lanes, matrix acceleration, and local cache behavior.

Aeon is designed for interactive local inference on models whose full parameter set exceeds a single GPU's VRAM.
